# SC2 Build Overlay

직접 손으로 쓴 스타크래프트 II 빌드오더를 인게임 화면 위에 오버레이로 띄우고,
게임 내 시계에 맞춰 자동으로 다음 단계를 짚어줍니다.

리플레이 파싱이나 외부 사이트 크롤링은 하지 않습니다. 빌드는 `builds/` 폴더에
직접 작성합니다.

## 실행

```bash
npm install
```

```bash
npm start
```

**제어창이 열리고, 앱은 정지 상태로 시작합니다.** `시작` 을 누를 때까지 SC2 를
읽지도 않고 화면에 아무것도 띄우지 않습니다. `Ctrl+Alt+S` 로도 시작/정지됩니다.

SC2 없이 UI를 확인할 때:

```bash
npm run dev
```

**`npm run dev` 는 SC2 를 전혀 읽지 않습니다.** 가짜 시계와 가짜
플레이어(`You` vs `Mock Opponent`)로 동작하는 개발용 모드이고, 제어창 상단에
`MOCK 모드` 배너가 뜹니다. 상태 칸의 값들도 전부 `가짜` 로 표시됩니다.
실제로 쓸 때는 반드시 `npm start` 를 쓰세요.

### 시작 / 정지 / 종료

**표시**와 **실행**은 별개입니다. 오버레이는 `0:00` 에 멈춘 채 화면에 떠 있을 수
있고, 시계는 `Ctrl+Alt+S` 를 누를 때 비로소 흐릅니다. 게임 들어가기 전에 빌드를
띄워놓고 확인한 다음, 게임이 시작되는 순간에 누르면 됩니다.

| | 뜻 |
| --- | --- |
| **시작 / 정지** (`Ctrl+Alt+S`) | 시계를 흐르게 하거나 멈춥니다. 정지 상태에서는 SC2 를 읽지 않습니다 (아래 **게임이 시작되면 자동으로 시작** 을 켠 경우는 예외). **오버레이는 그대로 화면에 남습니다** (`0:00` 에 멈춘 상태). |
| | **정지하면 빌드오더 진행이 첫 단계로 돌아갑니다.** 고른 빌드는 유지되고 위치만 초기화되므로, 다시 시작하면 항상 처음부터입니다. |
| **표시 / 숨김** (`Ctrl+Alt+O`) | 오버레이를 화면에서 넣고 뺍니다. 실행 여부와 무관하게 언제든 동작합니다. |
| **종료** (`Ctrl+Alt+Q`) | 앱을 끝냅니다. 제어창의 `종료` 버튼, 트레이 메뉴에도 있습니다. |

`npm start` 하면 오버레이가 `0:00` 에 멈춘 채로 떠 있고 제어창은 `정지됨` 입니다.
아무것도 폴링하지 않습니다.

제어창을 닫아도 앱은 트레이에 남습니다 (실행 중인 오버레이가 창 정리 때문에
꺼지면 안 되니까요). 트레이 아이콘을 클릭하면 제어창이 다시 열립니다.

앱을 열자마자 바로 시작하고 싶으면 제어창에서 **앱을 열면 바로 시작** 을 켜세요.

### 게임이 시작되면 자동으로 시작

`Ctrl+Alt+S` 를 손으로 누르는 대신 앱이 게임 시작을 알아서 잡게 할 수 있습니다.
제어창 설정의 **게임이 시작되면 자동으로 시작** 입니다. 기본값은 꺼짐입니다.

켜두면 정지 상태일 때 1초마다 `localhost:6119` 를 확인하고, 게임에 들어간 것이
확인되는 순간 시작합니다. 제어창은 그동안 **`대기 중`** 으로 표시됩니다. 게임이
끝나고 `Ctrl+Alt+S` 로 정지하면 다시 대기 상태로 돌아가므로, 연속으로 여러 판을
할 때 매 판 시작 시점을 신경쓰지 않아도 됩니다.

실행 중에는 감시를 멈춥니다 (이미 시작했으니 다시 시작할 일이 없습니다). 옵션을
끄면 즉시 감시도 멈춥니다.

> 정지 상태에서 아무것도 폴링하지 않는다는 원칙의 유일한 예외입니다. 이 옵션을
> 켜는 동안만 1초 간격으로 읽습니다 (실행 중 간격은 250ms 입니다).

## 중요: SC2 그래픽 설정

SC2 를 **`전체 화면(창 모드)`** 로 두어야 오버레이가 게임 위에 올라옵니다.
진짜 전체 화면(독점 모드)에서는 일반 윈도우가 위로 올라갈 수 없습니다.

## 게임과 어떻게 동기화되나

SC2 클라이언트가 로컬에 열어두는 읽기 전용 HTTP 엔드포인트를 250ms 마다 읽습니다.

- `http://localhost:6119/game` → `displayTime`(인게임 시계), 플레이어, 종족
- `http://localhost:6119/ui` → 활성 화면 목록 (메뉴에 있는지 게임 중인지 판별)

인게임 시계는 실제 시간과 **1:1** 입니다. 빌드오더에 적는 시각도 인게임 시계
기준이므로 별도 환산 없이 그대로 비교합니다. 그리고 이 앱은 자체 타이머로 초를
세지 않고 매번 `displayTime` 을 읽기만 하므로, 오차가 누적되지 않고 일시정지·
재접속에도 알아서 맞습니다.

메모리 접근, 프로세스 인젝션, 입력 자동화는 일절 없습니다. 게임에 쓰는 것도 없고
순수하게 읽기만 합니다.

**인구수는 이 API로 얻을 수 없습니다.** 그래서 자동 진행은 시간 기준만
동작합니다. 인구수를 보고 따라가려면 `Ctrl+Alt+M` 으로 수동 모드로 바꾸고
`Ctrl+Alt+←/→` 로 직접 넘기세요.

## 빌드오더 작성 — 편집기

`Ctrl+Alt+E` (또는 트레이 메뉴 → 빌드오더 편집기) 로 편집기 창이 열립니다.
표에 채워 넣으면 파일 내용이 실시간으로 미리보기에 나오고, 저장하면 `builds/` 에
바로 쓰입니다.

- **현재 시각으로 추가** — SC2 가 게임 중이면 인게임 시계를 그대로 찍어 단계를
  추가합니다. 한 판 하면서 타이밍을 받아쓰는 게 손으로 계산하는 것보다 빠릅니다.
  `npm run dev` 의 가짜 시계에서도 동작합니다.
- **행동 칸에서 Enter** — 15초 뒤 시각으로 다음 줄을 만들고 커서를 옮깁니다.
- **구간(`[...]`)은 표에 열이 없습니다.** 파일에 있는 구간은 저장해도 그대로
  보존되고 (미리보기에서 확인 가능), 새 단계는 바로 위 단계의 구간을
  이어받습니다. 구간 이름을 고치거나 새로 나누려면 텍스트 에디터로 여세요.
- **시간순 정렬** — 저장할 때도 항상 시간순으로 정렬되므로, 순서가 뒤섞여도
  파일은 정상입니다. 표에서 눈으로 보기 좋게 맞추는 용도입니다.
- **기존 텍스트 붙여넣어 가져오기** — 이 포맷으로 된 텍스트를 표로 되돌립니다.
- **삭제** — 파일을 휴지통으로 옮깁니다 (되돌릴 수 있음).
- `Ctrl+S` 로도 저장됩니다.

경고가 나오는 경우:

- 시간이 비어 있는 단계는 저장되지 않습니다.
- 같은 구간 이름이 시간순으로 보면 두 군데로 나뉘는 경우 — 어떤 단계의 시간을
  구간 경계 밖으로 옮겼는데 구간 이름을 안 바꿨을 때 생깁니다.
- `#` 주석이 있는 파일을 편집기로 열면, 저장 시 주석이 사라진다고 알려줍니다.
  편집기는 구조화된 데이터로 파일을 다시 만들기 때문에 주석은 보존하지 못합니다.
  주석을 지키려면 그 파일은 텍스트 에디터로 편집하세요.

## 빌드오더 작성 — 직접 손으로

편집기를 쓰지 않고 `builds/` 폴더에 `.txt` 파일을 만들어도 됩니다. 저장하는 순간
오버레이가 다시 읽으므로 재시작할 필요가 없습니다.

```
name: TvZ 리퍼 앞마당
race: T
vs: Z
slot: 4
notes: 아무 메모

[오프닝]
0:12  @14  보급고
0:20  @16  병영
0:40  @16  정련소        // 리퍼 나오면 바로
1:12  @19  사령부 (앞마당)
```

### 문법

| 요소 | 설명 |
| --- | --- |
| `name:` `race:` `vs:` `slot:` `notes:` | 파일 맨 위 헤더. 첫 단계 이전에만 인식됩니다. |
| `0:20` | **필수.** 인게임 시계 기준 `M:SS`. 자동 진행의 유일한 기준입니다. |
| `@16` | 선택. 인구수 배지 (표시 전용). |
| `// 메모` | 선택. 해당 단계 아래에 작게 붙습니다. |
| `[구간 이름]` | 선택. 구간 구분선. |
| `# ...` | 줄 전체 주석. 무시됩니다. |

`race` / `vs` 는 `T` `Z` `P` `R` 또는 `테란` `저그` `프로토스`, `*`(아무 종족)
모두 인식합니다. `vs` 를 생략하면 `*` 로 취급합니다.

`race` 와 `vs` 를 채워두면, 게임이 시작될 때 매치업에 맞는 빌드를 자동으로
고릅니다 (설정에서 끌 수 있음). 이때 둘 중 누가 나인지 알아야 하는데, 자세한
내용은 [내 플레이어 이름](#내-플레이어-이름) 을 보세요.

파싱 못 한 줄은 잠금 해제 상태의 패널 아래쪽에 몇 번째 행인지 함께 표시됩니다.

## Vespene.gg 빌드 한글로 가져오기

Vespene.gg 에서 빌드를 **JSON 으로 익스포트**한 뒤 한글 빌드오더로 변환합니다.
사이트를 긁지 않습니다 — 직접 내보낸 파일을 읽을 뿐입니다.

### 편집기에서 (권장)

`Ctrl+Alt+E` → **가져오기 — Vespene.gg 익스포트 / 텍스트** → `Vespene.gg JSON 열기…`

익스포트에 들어있는 분기가 **승률·표본과 함께** 목록으로 나옵니다:

```
    68판  승률 57%  106단계  Raven + Starport Tech Lab (Lib/Ra…
    68판  승률 68%  104단계  Barracks Tech Lab (Bio Tech)
  ▶ 53판  승률 81%  110단계  Raven + Starport Tech Lab (Lib/Raven) → B…
    35판  승률 54%   95단계  Bunker (Defense) + Barracks Tech Lab ...
    25판  승률 60%   90단계  Cyclone + Barracks Tech Lab (Bio Tech)
```

> **익스포트 하나에 빌드 하나가 아닙니다.** 사이트가 그 세션에서 열어본 종족
> 트리를 전부 담아 보내므로, PvZ 익스포트 안에 직전에 보던 저그 빌드가 그대로
> 들어있습니다. 앱은 `race` 가 지목하는 트리만 보여주고, 제외한 것은 보고합니다.
> 목록 위에 `protoss-build.json — ... · Protoss 트리 8개 분기` 로 어느 트리를
> 골랐는지 표시됩니다.

**메인이 항상 최선은 아닙니다.** 클릭하면 그 분기가 바로 표에 채워지고, 아래
세 옵션을 바꾸면 즉시 다시 변환됩니다:

- **사이트 메모 포함 (영어 문장)** — 기본 꺼짐
- **상황부 단계 포함** — 기본 켜짐
- **반복 생산 완전 제외** — 기본 꺼짐 (기본은 "계속 생산" 한 줄로 압축)

파일 이름을 정하고 **저장**을 누르면 `builds/` 에 들어갑니다. 저장 전까지는
`저장 안 됨` 상태이므로 마음껏 옵션을 바꿔보셔도 됩니다.

### 명령줄에서

```bash
node tools/import-build.js 내려받은파일.json --list
```

먼저 `--list` 로 분기를 봅니다. 익스포트에는 분기가 여러 개 들어있고 각각 승률이
붙어 있습니다:

```
  ▶ main         68판  승률  57%   106단계  Raven + Starport Tech Lab (Lib/Ra…
    cbr211       68판  승률  68%   105단계  Barracks Tech Lab (Bio Tech)
    cbr322       53판  승률  81%   110단계  Raven + Starport Tech Lab → B…
```

그중 하나를 골라 `builds/` 에 저장합니다:

```bash
node tools/import-build.js 내려받은파일.json --branch=cbr322 --slot=7
```

| 옵션 | |
| --- | --- |
| `--list` | 분기 목록만 보고 끝냅니다 |
| `--branch=<id>` | 변환할 분기 (기본: 메인) |
| `--slot=<1-9>` | 핫키 슬롯을 헤더에 넣습니다 |
| `--out=<이름.txt>` | `builds/` 에 쓸 파일명 |
| `--stdout` | 저장하지 않고 화면에 출력 |
| `--drop-filler` | 반복 생산을 아예 제외 |
| `--no-situational` | 프로가 가끔만 하는 단계 제외 |
| `--no-notes` | 사이트의 코칭 메모 제외 |
| `--min-freq=<0~1>` | 상황부 단계의 빈도 하한 (기본 0.25) |

### 변환이 실제로 하는 일

익스포트는 오버레이가 쓸 수 있는 것보다 훨씬 상세해서, 변환은 **무엇을 버릴지**
정하는 작업입니다.

- **반복 생산 압축** — 사이트는 해병 한 기마다 한 줄씩 넣습니다 (한 빌드에 100줄
  가까이). 이걸 그대로 두면 실제 결정이 묻히므로 `해병 계속 생산` 한 줄로
  합칩니다. 손으로 쓴 빌드에서 쓰시는 표기와 같습니다.
- **애드온 이름 완성** — `TechLab` 만으로는 무슨 기술실인지 알 수 없습니다.
  `addonOf` 로 부모 건물을 찾아 `병영 기술실` / `우주공항 기술실` 로 만듭니다.
- **변형 분리** — 사령부가 1:45 에 궤도 사령부가 되면, 그 시각에 별도 단계로
  나옵니다.
- **구간 자동 부여** — 익스포트의 `opening` / `early` / `mid` 를 시간 구간으로
  환산해 `[오프닝]` `[초반]` `[중반]` 을 붙입니다.
- **상황부 표시** — 프로가 31% 만 하는 벙커는 `// 상황부 31%` 로 표시하고,
  빈도가 하한 미만이면 제외합니다.
- **인구수 0 처리** — 익스포트는 인구수를 모를 때 `0` 을 쓰므로 없음으로 봅니다.

### 번역되지 않은 용어

용어 사전은 `src/main/translate.js` 에 있고 3종족 175개가 들어 있습니다. 표기는
`builds/` 의 손으로 쓴 빌드와 같은 공식 한국어 명칭입니다.

**사전에 없는 용어는 영어로 남고 반드시 보고됩니다.** 조용히 반쯤 번역된 빌드는
안 된 것보다 나쁘기 때문입니다:

```
  ⚠ 번역 못 한 용어 1개: SomeNewThing

  사전에 추가하려면 src/main/translate.js 의 TERMS 에 넣으세요:
    SomeNewThing: '',
```

### 아직 안 되는 것

**코칭 메모는 영어 그대로 옵니다** (`// Scout with Reaper.`). 자유 서술 문장이라
용어 사전으로는 처리할 수 없습니다. 필요 없으면 `--no-notes` 로 빼세요.

## 빌드 슬롯 (Ctrl+Alt+1 ~ 9)

파일에 `slot: 3` 을 적으면 `Ctrl+Alt+3` 으로 그 빌드를 불러옵니다.
게임 중에 눌러도 되고, 누르면 상단에 어떤 빌드로 바뀌었는지 잠깐 표시됩니다.

```
slot: 1   → Ctrl+Alt+1
slot: 2   → Ctrl+Alt+2
...
slot: 9   → Ctrl+Alt+9
```

기본으로 들어있는 파일들이 이렇게 잡혀 있습니다:

| 키 | 파일 | 빌드 |
| --- | --- | --- |
| `Ctrl+Alt+1` | `builds/1-tvt.txt` | TvT 정석 — 사신 확장 → 1/1/1 밤까마귀 전차 |
| `Ctrl+Alt+2` | `builds/2-tvp.txt` | TvP 정석 — 사신 확장 → 1/1/1 지뢰/해방선 → 바이오 |
| `Ctrl+Alt+3` | `builds/3-tvz.txt` | TvZ 정석 — 사령부 선건설 → 빠른 3사령부 3병영 바이오 |
| `Ctrl+Alt+4` | `builds/4-zvt.txt` | ZvT 정석 — 3부화장 → 저글링/맹독충 → 히드라리스크 |
| `Ctrl+Alt+5` | `builds/5-zvp.txt` | ZvP 정석 — 부화장 선건설 → 3부화장 → 바퀴/궤멸충/히드라 |
| `Ctrl+Alt+6` | `builds/6-zvz.txt` | ZvZ 정석 — 산란못 선건설 → 3부화장 → 바퀴/궤멸충 |

프로토스(`PvT`/`PvP`/`PvZ`)는 비어 있습니다. `slot: 7` ~ `9` 로 직접 추가하세요.

**빌드의 시간은 검증된 값이 아닙니다.** 인구수 트리거는 표준에 가깝지만, 초 단위
시각은 패치·맵·일꾼 동선에 따라 달라집니다. 편집기의 **현재 시각으로 추가** 로
실제 한 판을 돌면서 자기 값으로 고쳐 쓰세요.

**슬롯으로 빌드를 바꾸면 시계가 `0:00` 으로 초기화되고 정지 상태가 됩니다.**
다른 빌드로 갈아타면서 이전 시계를 들고 가면 새 빌드의 중간부터 시작하게 되는데,
그건 빌드를 바꾸는 의도가 아니기 때문입니다. 준비되면 `Ctrl+Alt+S` 를 다시
누르세요. (실제 게임에서는 다시 시작하는 순간 게임 시계를 그대로 읽으므로,
`0:00` 은 정지해 있는 동안만 유지됩니다.)

**`slot:` 을 적어둔 빌드는 파일을 추가해도 번호가 바뀌지 않습니다.** 손에 익은
번호가 밀리면 안 되니까요. `slot:` 이 없는 파일들은 남은 번호에 파일명 순서로
자동 배정되므로, 고정하고 싶은 빌드에는 꼭 `slot:` 을 적어주세요.

같은 번호를 두 파일이 선언하면 먼저 온 파일이 가져가고, 나중 파일은 자동 배정으로
넘어가면서 경고가 표시됩니다.

### 목록 순서

빌드 목록은 **슬롯 번호 순서**입니다. 순서를 바꾸려면 `slot:` 을 바꾸면 됩니다 —
편집기의 **슬롯** 드롭다운이나 파일 헤더에서요. 목록 순서와 핫키가 항상 일치합니다.

`slot:` 이 없는 빌드는 남은 번호를 자동으로 받고, 10번째 이후는 맨 뒤에 파일명
순서로 붙습니다.

편집기의 **슬롯** 드롭다운은 각 번호를 쓰는 빌드 이름을 함께 보여줍니다.
지금 편집 중인 빌드가 고른 번호에도 그 이름이 붙어서, 저장 후 목록이 어떻게
보일지 그대로 읽힙니다.

단, **이미 다른 빌드가 쓰는 번호**를 고르면 그 빌드 이름이 그대로 남습니다 —
누구와 교환될지가 저장 전에 봐야 하는 정보이기 때문입니다.

이미 쓰이는 번호를 고르고 저장하면 **두 빌드의 번호가 서로 바뀝니다** — 상대 빌드가 이 빌드의
원래 번호를 받습니다. 순서를 맞바꾸는 게 한 번에 됩니다.

교환된 내용은 저장 후 하단에 `… 저장 · N단계 · 올인 → 7번` 으로 표시됩니다.
상대 파일은 `slot:` 줄만 고쳐지므로 주석과 나머지 내용은 그대로 남습니다.

자동 배정된 번호(= 파일에 `slot:` 이 없는 빌드가 받은 번호)는 교환 대상이
아닙니다. 그 빌드는 알아서 다른 빈 번호로 옮겨갑니다.

슬롯으로 빌드를 부르면 그 빌드가 고정되어 매치업 자동 선택을 덮어씁니다.
얼마나 오래 고정되는지는 [자동 선택과 고정](#자동-선택과-고정) 을 보세요.
트레이 아이콘 메뉴의 **빌드 슬롯** 항목에서도 같은 목록을 볼 수 있습니다.

## 자동 선택과 고정

제어창의 **종족 매치업으로 자동 선택** 체크박스가 두 방식을 가릅니다.

**기본은 꺼짐**입니다 — 슬롯 핫키로 직접 고르는 게 기본 방식입니다.

| | 슬롯 핫키 / 목록 클릭 | 게임이 끝나면 | 앱 재시작 |
| --- | --- | --- | --- |
| **켜짐** | 그 게임만 덮어씀 | 자동 선택으로 복귀 | 고정 없음 |
| **꺼짐** (기본) | 이게 유일한 선택 수단 | 유지 | 유지 |

켜짐 상태에서 고정된 빌드는 목록에 `고정 — 눌러서 해제` 로 표시되고, 그 줄을 다시
누르면 즉시 자동 선택으로 돌아갑니다. 정찰하고 급하게 올인으로 바꾼 것이 다음
게임까지 따라오지 않습니다.

### ★ 즐겨찾기

같은 매치업 빌드가 여러 개면 자동 선택이 어느 것을 골라야 할지 정해야 합니다.
빌드 목록 왼쪽의 ★ 를 누르면 그 빌드가 우선됩니다.

우선순위는 이렇습니다:

1. `vs` 가 상대 종족과 **정확히 일치** — 즐겨찾기한 것 우선
2. `vs: *` **범용** — 즐겨찾기한 것 우선
3. 같으면 **슬롯 번호가 낮은 것**

정확 일치가 항상 범용을 앞섭니다. TvZ 전용 빌드가 있으면 즐겨찾기한 범용
빌드보다 먼저 잡힙니다.

즐겨찾기는 파일이 아니라 설정(`config.json`)에 저장됩니다 — 빌드 내용이 아니라
개인 취향이기 때문입니다.

★ 가 하나도 없어도 자동 선택은 정상 동작합니다. 매치업 순위로 고르고, 동점이면
슬롯 번호가 낮은 것이 이깁니다. ★ 는 동점을 깰 때만 쓰입니다.

### 내 플레이어를 못 찾으면

사람 상대 1v1 에서 **내 플레이어 이름**이 비어 있거나 틀리면 매치업을 읽을 수
없습니다. 이때도 아무것도 띄우지 않고 이유를 말합니다:

```
내 플레이어를 못 찾았습니다.
제어창 설정에 내 플레이어 이름을 넣으세요.
```

이름 없이 매치업을 추측하면 절반은 틀리므로, 추측하지 않습니다.

### 맞는 빌드가 없으면

자동 선택 상태에서 그 매치업에 맞는 빌드가 하나도 없으면 **아무것도 띄우지
않습니다.** 오버레이에 이렇게 나옵니다:

```
ZvT 빌드가 없습니다.
Ctrl+Alt+숫자 로 직접 고르거나 편집기에서 만드세요.
```

엉뚱한 매치업 빌드를 띄우면 맞는 것처럼 보여서 그대로 따라가게 되므로, 그보다는
비워두는 쪽이 낫습니다. (자동 선택이 꺼져 있거나 게임 전이면 목록의 첫 빌드를
그대로 보여줍니다.)

## 내 플레이어 이름

매치업 자동 선택은 "내가 무슨 종족이고 상대가 무슨 종족인지" 를 알아야 동작하는데,
**SC2 는 둘 중 누가 로컬 플레이어인지 알려주지 않습니다.** `/game` 은 플레이어
배열만 줄 뿐입니다. 그래서 이름으로 구분합니다.

- **상대가 AI 면 비워두셔도 됩니다.** 사람이 한 명뿐이니 자동으로 구분됩니다.
- **사람 상대 1v1 이면 필요합니다.** 둘 다 사람이라 이름 없이는 구분이 안 됩니다.

### 무엇을 입력하나

**배틀태그(`이름#1234`)가 아니라 SC2 가 알려주는 이름**입니다. 추측하지 않아도
됩니다 — 게임에 들어가면 제어창의 이 칸 아래에 SC2 가 보고한 플레이어 이름이
그대로 표시됩니다:

```
이 게임의 플레이어: 내이름 · 상대이름 — 내 쪽을 위에 입력
```

보이는 대로 입력하면 초록색으로 바뀌면서 `인식됨` 이 됩니다.

대소문자는 무시하지만 **그 외에는 정확히 같아야** 합니다. 부분 일치나 `#` 앞부분만
떼어내는 처리는 없습니다. 틀리면 에러가 나지 않고 **매치업 자동 선택만 조용히
안 됩니다** — 그래서 인식 여부를 화면에 표시합니다.

터미널로 확인하고 싶으시면 게임 안에서:

```bash
curl -s http://localhost:6119/game
```

`players` 배열의 `name` 값이 비교 대상입니다.

## 유닛·건물 그림 (아이콘)

제어창의 **오버레이 → 아이콘** 에서 `없음` / `작게` / `크게`. 기본값은 `없음`
입니다.

| | |
| --- | --- |
| **없음** | 글자만. 게임을 아는 사람이 가장 빨리 읽습니다. |
| **작게** | 줄 높이를 그대로 두고 글자 왼쪽에 작은 그림. |
| **크게** | 그림을 키우고 줄도 넓힙니다. 게임을 잘 모르는 사람이 게임 화면의 버튼과 대조하기 좋습니다. |

글자는 어느 모드에서도 사라지지 않습니다. **그림이 '무엇을', 글자가 '몇 개를'**
알려주기 때문입니다 (`해병 2기, 불곰 1기` 는 그림만으로 표현되지 않습니다).

아이콘을 켜면 **창이 그만큼 넓어집니다.** 아이콘 열을 글자 자리에서 빼앗으면 긴
단계가 잘리기 때문입니다.

설정은 PC 마다 따로 저장되므로(`%APPDATA%/sc2-build-overlay/config.json`), 빌드
파일은 그대로 공유하면서 각자 다른 모드로 볼 수 있습니다.

### 어떻게 그림을 찾나

단계 문장에서 한글 용어를 찾습니다. **긴 것이 이깁니다** — `병영 기술실` 이
`병영` 보다, `원거리 공격 2단계` 가 `원거리 공격` 보다 먼저 잡힙니다. 한 단계에
그림은 하나만 붙습니다. 손으로 쓴 빌드를 세어보면 95% 의 단계가 딱 한 가지를
말하므로, 열 너비를 하나로 고정하는 편이 모든 줄의 글자 시작점이 맞아 훑어보기
쉽습니다.

용어를 못 알아본 단계는 그냥 글자만 나옵니다 — `상대 네 번째 기지 압박` 처럼
그림이 없는 게 맞는 문장도 있습니다.

### 그림 파일은 설치본에 없습니다

**그림은 설치 파일에 들어 있지 않습니다.** 제어창의 **오버레이 → 그림 내려받기**
를 눌러야 받아옵니다. 아이콘 기본값이 `없음` 이므로, 안 쓰실 거면 아무것도
받지 않습니다.

이유는 저작권입니다. 그림은 게임 파일에서 추출한 것이고 **Blizzard
Entertainment 의 저작물**입니다. 설치 파일에 담아 배포하면 그 저작물을 복제해
배포하는 것이 됩니다. 대신 각 PC 가 필요할 때 공개된 원본에서 직접 받아갑니다 —
[sc2-planner](https://github.com/BurnySc2/sc2-planner) 저장소이고, 예전부터
`tools/fetch-icons.js` 가 하던 일과 같습니다.

설치본에 들어가는 것은 `manifest.json` 하나입니다. 한글 용어와 파일 이름을 잇는
표이고, 이건 이 프로젝트가 만든 자료입니다.

개발할 때는 `assets/icons/` 에 그대로 두고 씁니다. 다시 받거나 새 용어를 추가한
뒤 표를 다시 만들려면:

```bash
node tools/fetch-icons.js
```

이미 있는 파일은 건너뜁니다.

`궤도 사령부` 만 아이콘이 없습니다. 비슷한 `사령부` 그림으로 대체하지
않았습니다 — 초보자가 사령부를 새로 짓는 것으로 오해할 수 있어서, 글자만 두는
쪽이 안전합니다.

## 오버레이 위치 옮기기

두 가지 방법이 있습니다.

1. **제어창 → 오버레이 → 위치** 에서 `↖ 좌상` `↗ 우상` `↙ 좌하` `↘ 우하` 중
   하나를 누르면 그 모서리로 붙습니다. 오버레이가 걸쳐 있는 모니터를 기준으로
   계산하므로 멀티 모니터에서도 맞습니다. (실행 중이고 표시 상태일 때만 활성)
2. **`Ctrl+Alt+L`** 로 잠금을 풀고 오버레이 **상단 제목 부분을 마우스로 끌면**
   원하는 위치에 놓을 수 있습니다. 끝나면 다시 `Ctrl+Alt+L` 로 잠그세요 —
   잠그지 않으면 오버레이가 게임 클릭을 먹습니다.

위치는 `config.json` 에 저장되어 다음 실행에도 유지됩니다.

## 효과음

자동 모드에서 **단계가 실제로 넘어갈 때** 짧은 알림음이 울립니다. 화면을 보지
않고도 다음 할 일이 왔다는 걸 알 수 있습니다.

- 제어창 **효과음** 칸에서 켜고 끄고, 볼륨(0~100%)을 조절합니다.
- **소리 확인** 버튼으로 게임 없이 볼륨을 맞출 수 있습니다. 볼륨 슬라이더를
  놓는 순간에도 한 번 울립니다.
- **수동 모드에서는 울리지 않습니다** — 직접 누른 것이니 알릴 필요가 없습니다.
- **미리 알림 N초** 를 켜두면 그만큼 앞당겨 울립니다.

음원 파일 없이 Web Audio 로 합성합니다 (`src/renderer/sound.js`). 음정·길이를
바꾸고 싶으면 그 파일의 `render()` 를 고치면 됩니다.

| `Ctrl+Alt+P` | (dev 모드) 가짜 시계 일시정지 |
| `Ctrl+Alt+0` | (dev 모드) 가짜 시계 0:00 으로 |

SC2 는 제어 그룹에 `Ctrl+숫자` / `Shift+숫자` 를 쓰므로 `Ctrl+Alt+숫자` 는 겹치지
않습니다. 다만 이 핫키들은 **시스템 전역으로 가로채기** 때문에, 만약 SC2 쪽에서
`Ctrl+Alt` 조합을 직접 지정해 쓰고 있다면 그 키는 게임에 전달되지 않습니다.
그럴 때는 `src/main/main.js` 의 `registerShortcuts()` 에서 조합을 바꾸세요.
등록에 실패한 핫키는 콘솔에 `hotkey unavailable: ...` 로 찍힙니다.

앱은 **한 번만 실행됩니다.** 두 번째로 열면 첫 번째가 전역 핫키를 이미 잡고 있어서
모든 단축키가 조용히 안 먹게 되므로, 두 번째 인스턴스는 즉시 종료되고 대신 실행
중인 앱의 제어창이 열립니다.

평소에는 **잠금** 상태라 마우스 이벤트가 그대로 게임으로 통과합니다.
오버레이 위치를 옮기려면 `Ctrl+Alt+L` 로 잠금을 풀어 헤더를 끌고, 끝나면 다시
잠그세요. 빌드 선택과 설정은 제어창에서 합니다.

## 제어창

`Ctrl+Alt+C` 또는 트레이 아이콘 클릭으로 엽니다. 앱에서 바꿀 수 있는 건 전부
여기 있습니다 — 오버레이 자체는 표시 전용입니다.

- **상태** — 위에서 아래로 좁혀지는 진단 사슬입니다

  | 줄 | 무엇을 보는가 |
  | --- | --- |
  | `SC2 클라이언트` | `localhost:6119` 응답 여부. `연결됨 · localhost:6119` / `대기 중 · SC2 미실행` |
  | `게임` | 메뉴인지 게임 안인지 (`/ui` 의 활성 화면 목록), 그리고 매치업 |
  | `시계` | `displayTime` — 인게임 시계. 자동 진행의 유일한 기준 |
  | `다음 단계` | 선택된 빌드에서 다음에 할 일 |

  `npm run dev` 에서는 전부 `가짜` 로 표시됩니다.
- **빌드** — 목록에서 클릭해 선택, 슬롯 번호 표시, 매치업 자동 선택 토글
- **오버레이** — 표시/숨김, 잠금, 자동/수동 모드, 미리 알림, 아이콘, 불투명도,
  크기, 지난·다음 단계 표시 개수, **위치 프리셋**

  **크기**를 바꾸면 글자만이 아니라 **창 자체가 같이 커지고 작아집니다.**
  높이는 실제로 그려진 내용에 맞춰지므로, 표시 단계 수를 늘리면 창도 그만큼
  길어지고 남는 투명 여백이 생기지 않습니다. 모서리에 붙여둔 오버레이는 그
  모서리를 유지한 채 크기가 변합니다 (우하단에 두면 왼쪽·위로 자랍니다).
- **효과음** — 단계가 넘어갈 때 알림음, 볼륨, 소리 확인 버튼
- **설정** — 내 플레이어 이름(아래 참고), 앱 열면 바로 시작, 게임이 시작되면
  자동으로 시작
- **핫키** — 전체 목록

설정은 `%APPDATA%/sc2-build-overlay/config.json` 에 저장됩니다.

### 개발용

오버레이·제어창·편집기 UI를 브라우저에서 확인하려면 (preload 브리지가
스텁으로 대체됩니다):

```bash
node tools/preview-server.js
```

- `http://localhost:4173/index.html` — 오버레이 (게임 화면 비슷한 배경 위)
- `http://localhost:4173/control.html`
- `http://localhost:4173/editor.html`

오버레이 프리뷰는 `builds/` 의 실제 파일을 읽습니다. 다른 빌드를 보려면
`PREVIEW_BUILD=3-tvz.txt node tools/preview-server.js`.

아이콘 모드를 보려면 `PREVIEW_ICONS=large`(또는 `small`) 를 함께 주세요.

`SC2_EDITOR=1` 을 주면 앱 시작 시 편집기 창이 바로 열립니다.

## 배포용 빌드

```bash
npm run dist
```

`dist/` 에 두 가지가 나옵니다:

| 파일 | 용도 |
| --- | --- |
| `SC2 Build Overlay Setup <버전>.exe` | NSIS 설치 파일. 설치 경로 선택 가능, 바탕화면·시작메뉴 바로가기 생성 |
| `SC2BuildOverlay-<버전>-portable.exe` | 설치 없이 실행하는 단일 파일 |

버전은 `package.json` 의 `version` 에서 옵니다. **외부에 내보낼 때만** 올리세요 —
개발 중 반복 빌드는 같은 번호로 다시 말면 됩니다. NSIS 설치 파일은 버전이 더
높아야 기존 설치를 덮어쓰기 업그레이드하므로, 남에게 준 뒤에 바뀐 게 있으면
반드시 올려야 합니다. 바뀐 내용은 [CHANGELOG.md](CHANGELOG.md) 에 적습니다.

각 76MB 정도입니다 (Electron 런타임 포함). 서명은 하지 않으므로 Windows
SmartScreen 경고가 뜹니다 — 코드 서명 인증서가 있으면 `build.win.certificateFile`
에 지정하면 됩니다.

`npm run pack` 은 설치 파일을 만들지 않고 `dist/win-unpacked/` 에 실행 가능한
폴더만 만듭니다 (빠른 확인용).

### 패키징된 앱에서 빌드 파일이 있는 곳

패키징하면 앱 자체는 읽기 전용 `app.asar` 이 되므로 **`builds/` 는 그 안에 둘 수
없습니다** — 편집기가 저장하고 파일 감시가 걸리는 폴더이기 때문입니다. 그래서
패키징된 앱은 `builds/` 를 여기에 둡니다:

```
%APPDATA%/sc2-build-overlay/builds/
```

첫 실행 때 `seed/` 의 내용이 여기로 복사됩니다. 이미 파일이 있으면 덮어쓰지
않습니다. 제어창의 **빌드 폴더** 버튼이 이 경로를 열어줍니다.

개발 실행(`npm start`)은 프로젝트의 `builds/` 를 그대로 씁니다.

### `seed/` — 배포판에 들어가는 것

패키징에는 **`seed/` 만** 들어갑니다. 개발용 `builds/` 는 들어가지 않습니다.

작업하다 보면 `builds/` 에 실험용 파일이 쌓이는데, 그게 배포판에 딸려 나가면
안 되기 때문입니다. 배포판이 무엇을 들고 나갈지는 `seed/` 에 무엇을 두느냐로
정해집니다 — 지금은 샘플 한 개입니다.

```
seed/1-tvt.txt        ← 배포판이 첫 실행 때 심는 샘플
builds/               ← 내가 쓰는 빌드들 (배포에 포함 안 됨)
```

샘플을 바꾸려면 `seed/` 의 파일을 교체하고 다시 빌드하세요.

## 아이콘

`assets/icon.ico` 를 트레이, 제어창·편집기 창(작업표시줄 포함), 그리고 설치
파일·실행 파일 아이콘에 씁니다.

**16 · 24 · 32 · 48 · 64 · 128 · 256** 을 모두 담은 멀티 사이즈 `.ico` 입니다.
그림 파일을 바꿨다면 이 명령으로 다시 만들 수 있습니다:

```bash
npm run icon
```

`tools/make-icon.js` 가 하는 일:

- 완전히 투명한 테두리를 재서 잘라냅니다 (아트워크가 프레임을 꽉 채우도록)
- 정사각형으로 맞추고 7종 크기로 리샘플해 하나의 `.ico` 로 묶습니다
- `--report` 를 주면 측정만 하고 아무것도 쓰지 않습니다
- `--margin=N` 으로 여백을 남기거나(양수), 더 파고들 수 있습니다(음수)
- 다른 파일을 원본으로 쓰려면 경로를 인자로 넘기세요 (`.ico` 또는 `.png`)

의존성 없이 Electron 의 `nativeImage` 로 처리합니다.

오버레이 창은 `skipTaskbar: true` 이고 프레임이 없어서 아이콘을 쓰지 않습니다.

## 알려진 한계

- 인구수·자원·유닛 수를 읽을 수 없습니다 (클라이언트 API 가 안 줍니다).
- 독점 전체 화면에서는 동작하지 않습니다.
- 게임을 나가면 수동 모드가 자동으로 풀립니다.
- 정지/시작은 진행 위치를 초기화합니다. 한 판 도중에 잠깐 껐다 켜면 처음부터가
  되므로, 오버레이만 잠깐 치우려면 정지가 아니라 `Ctrl+Alt+O` 숨김을 쓰세요.
- `displayTime` 이 진실이므로 일시정지·재접속 시에도 알아서 맞습니다. 대신
  관전·리플레이에서도 그대로 따라갑니다 (오버레이에 `리플레이` 배지로 표시).
- 오버레이 배지는 실제 게임 중 알아야 할 것만 띄웁니다 — `수동`, `리플레이`.
  `npm run dev` 의 가짜 시계 여부는 제어창과 편집기에서 `(mock)` 으로 확인하세요.
